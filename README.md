# АС «ВРДО ПДГ»

Автоматизированная система «Ввод режима по напряжению в допустимую область при формировании ПДГ».
Система загружает мегаточку (МТ) `smzu_mega_act.mptsmz` и файл топологии `smp_smzu.csv`, для каждого часа
и каждого контрольного пункта (КП) вводит напряжение в границы графика, изменяя загрузку управляемых СКРМ,
состояние коммутируемых СКРМ и заданное напряжение генераторов по таблицам эффективности, и дописывает
изменения во второй блок файла `smp_smzu.csv`.

## Структура решения

| Проект | Каталог | Уровень (диаграмма C3) | Состав |
| --- | --- | --- | --- |
| `View` | `View` | Представление | Главная форма, окна «Загрузка данных», «Таблица эффективности», формы «Напряжение по часам», «Архив расчетов», «Сравнение расчетов», справка (Windows Forms без сторонних библиотек оформления) |
| `Model` | `Main` | Прикладной | `DataLoadService`, `VoltageRegulationService`, `CalculationArchiveService`, `ResultExportService`, `EfficiencyTableService`, протокол расчета, сущности и интерфейсы модулей инфраструктуры |
| `Infrastructure` | `Infrastructure` | Инфраструктура | `ModelDataRepository` (SQLite, Microsoft.Data.Sqlite), `SmpSmzuCsvReader`, `SmpSmzuCsvWriter`, `CkModel` |
| `Infrastructure.Bars` | `Infrastructure.Bars` | Инфраструктура | `RastrAdapter` — взаимодействие с ПО «Барс» через интерфейс IRastr библиотеки ASTRALib.dll |
| `Tests` | `Tests` | — | Модульные тесты NUnit с тестовой реализацией модуля взаимодействия с ПО «Барс» |

Система работает с готовой БД SQLite (`VrdoPdg.db`) и не создает и не заполняет ее.

## Требования

- Windows 11 (или совместимая ОС семейства Windows), .NET SDK 10, Microsoft Visual Studio 2026.
- ПО «Барс» с библиотекой `ASTRALib.dll`. Ссылка на библиотеку задана путем `..\..\..\..\RastrWin3\ASTRALib.dll`
  относительно каталогов проектов `Infrastructure.Bars` и `View` (как в прототипе); при другом расположении
  исправьте `HintPath` в этих проектах.
- Платные библиотеки оформления не требуются: кнопки, панели со скругленными углами, поле поиска,
  полоса хода расчета и окна без рамки реализованы средствами Windows Forms в каталогах `View/Controls`
  и `View` (`RoundedButton`, `RoundedPanel`, `SearchBox`, `SlimProgressBar`, `BorderlessForm`).
- Если библиотека ASTRALib 32-разрядная, запускайте конфигурацию `x86`.

## Настройка

Файл `appsettings.json` рядом с исполняемым файлом:

| Параметр | Назначение | По умолчанию |
| --- | --- | --- |
| `DatabasePath` | Путь к файлу БД SQLite (относительный путь — от каталога программы) | `VrdoPdg.db` |
| `ResultsDirectory` | Каталог результатов ПО Барс-МДП | `D:\BarsMDP\Results` |
| `CsvDecimalSeparator` | Десятичный разделитель в `smp_smzu.csv`, если его нельзя определить по исходному файлу | `,` |
| `LowerVoltageBound`, `UpperVoltageBound` | Границы графиков напряжений до реализации запроса к ОИК «СК-11», кВ | `500`, `525` |

При запуске система проверяет, что файл БД существует и содержит таблицы системы. Если файла нет
или в нем нет нужных таблиц, выводится сообщение об ошибке и программа завершается; новый файл БД
не создается. По умолчанию БД ищется рядом с исполняемым файлом (`VrdoPdg.db`).

## Сборка и тесты

```bash
dotnet build View.sln -p:Platform=x86
```

```bash
dotnet test Tests/Tests.csproj
```

Модульные тесты не требуют ПО «Барс»: алгоритм проверяется на тестовой модели режима
(`Tests/Fakes/FakeRastrAdapter.cs`). Тесты чтения и записи БД выполняются на копии рабочей БД, путь к которой
задается переменной среды `VRDO_PDG_TEST_DATABASE`; без нее эти тесты пропускаются:

```powershell
$env:VRDO_PDG_TEST_DATABASE = "C:\путь\к\VrdoPdg.db"; dotnet test Tests/Tests.csproj
```

## Принятые допущения

- Границы графиков напряжений в КП временно постоянны (500–525 кВ) для всех КП и часов: `CkModel`
  не обращается к Public API ОИК «СК-11».
- Ввод режима выполняется по напряжению основного узла КП (`Node.is_main = 1`).
- Номер генератора в БД (`Generator.num_node`) — номер узла подключения в таблице «Узлы» МТ. Заданное
  напряжение берется из столбца `vzd` этого узла и изменяется шагами по 0,3 кВ; загрузка и пределы реактивной
  мощности — из столбцов `qg`, `qmin`, `qmax` узла (PQ-диаграмма используется, если в узле один работающий
  генератор). Запись об изменении заданного напряжения (код 01) формируется для этого узла.
- Управляемое СКРМ разгружается до Qmin (загружается до Qmax) установкой одинаковых пределов
  реактивной мощности узла; в файл записывается код 03 с этими пределами.
- Управляемое СКРМ считается отключенным, если отключен его узел или оба предела реактивной мощности равны 0.
- Коммутируемые СКРМ не изменяются в часах, для которых их состояние задано в `smp_smzu.csv` (код 20).
- Изменения одного часа не переносятся на следующий час; каждый расчет начинается с исходной МТ.
